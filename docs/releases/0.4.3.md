# CloudGPT 0.4.3 – checked ChatGPT connection handoff

The previous installer checked the Mac service but left the ChatGPT setup disconnected from that result. A deleted connector could still be referenced by an old private plugin archive, and a tunnel ID entered in Server URL mode produced an invalid URL error.

The updater also waits for asynchronous launchd deregistration before restarting, removes the previous health-address cache and checks the running tunnel ID. This prevents an old registration and readiness response from producing a premature success while the service is actually stopping. A stop timeout blocks runtime replacement.

`Install CloudGPT.command` now updates or installs the service and opens a checked local connection assistant. `Update.command` uses the same complete flow. `Connect ChatGPT.command` rechecks and reopens only the connection step.

The assistant verifies the installed package version, local readiness, running tunnel ID and embedded plugin ZIP checksum. It supplies the tunnel ID, makes the required **Tunnel-ID** field explicit and includes the clean branding/skill archive in the same macOS download. It never generates a tunnel URL or copies a private app binding. Local status URLs must use loopback, and redirects are rejected. Existing working ChatGPT connections should be kept and refreshed.

Mac readiness and actual ChatGPT installation are reported separately. The account step still uses ChatGPT’s supported custom MCP dialog; the installer cannot bypass workspace permissions or verify an account installation without a successful ChatGPT read. The generated page is an offline snapshot, not a live status dashboard. Use Connect ChatGPT.command to recheck it.

Validation: typecheck; 597 source tests; 21 protocol/permission tests against the built server; checksums and ZIP inspection. The checked local assistant and safe update path were exercised on an existing Mac installation. ChatGPT account reconnection, imported branding/skill behavior, mobile access and real macOS Automation permissions remain separate acceptance checks.

Download the macOS ZIP, unpack it separately and open **Install CloudGPT.command**. The background service, credentials, tunnel ID and access mode retain the existing upgrade/rollback behavior. No extra Node packages are installed at runtime. Both ZIPs are unbound public artifacts and contain no account-specific app ID or keys.
